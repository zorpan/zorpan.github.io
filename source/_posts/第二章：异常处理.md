## 2.1 异常体系结构

```
Throwable
├── Error（程序无法处理的严重错误）
│   ├── OutOfMemoryError
│   ├── StackOverflowError
│   ├── NoClassDefFoundError
│   └── ...
└── Exception（程序可以处理的异常）
    ├── RuntimeException（非受检异常）
    │   ├── NullPointerException
    │   ├── ArrayIndexOutOfBoundsException
    │   ├── ClassCastException
    │   ├── IllegalArgumentException
    │   ├── NumberFormatException
    │   └── ConcurrentModificationException
    └── 受检异常（Checked Exception）
        ├── IOException
        ├── SQLException
        ├── ClassNotFoundException
        └── FileNotFoundException
```

## 2.2 受检异常与非受检异常

| 类型 | 编译器检查 | 常见示例 | 处理方式 |
|------|-----------|---------|---------|
| **受检异常** | 必须处理 | IOException、SQLException | try-catch 或 throws 声明 |
| **非受检异常** | 不强制处理 | NullPointerException、IndexOutOfBoundsException | 程序逻辑应避免 |
| **Error** | 不应处理 | OutOfMemoryError | 程序通常无法恢复 |

```java
// 受检异常：必须处理
public void readFile() throws IOException {  // 必须声明
    FileReader fr = new FileReader("test.txt");
}

// 非受检异常：可以不处理
public void divide(int a, int b) {
    int result = a / b;  // ArithmeticException，编译器不强制处理
}
```

> **面试考点：Error 和 Exception 的区别？**
> Error 是程序无法处理的严重错误（如 OOM），通常由 JVM 抛出，程序不应捕获；Exception 是程序可以处理的异常，分为受检异常（必须处理）和运行时异常（可处理可不处理）。

## 2.3 try-with-resources 与资源管理

### 2.3.1 传统方式的问题

```java
// 传统写法：资源可能泄露
FileInputStream fis = null;
try {
    fis = new FileInputStream("test.txt");
    // 处理文件
} catch (IOException e) {
    e.printStackTrace();
} finally {
    if (fis != null) {
        try {
            fis.close();  // close 也可能抛异常！
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

### 2.3.2 try-with-resources（JDK 7+）

```java
// 自动关闭实现了 AutoCloseable 接口的资源
try (FileInputStream fis = new FileInputStream("test.txt");
     BufferedReader br = new BufferedReader(new InputStreamReader(fis))) {
    String line = br.readLine();
} catch (IOException e) {
    e.printStackTrace();
}
// fis 和 br 在 try 块结束后自动关闭（即使发生异常）
```

### 2.3.3 多资源关闭顺序

```java
try (ResourceA a = new ResourceA();
     ResourceB b = new ResourceB()) {
    // 业务逻辑
}
// 关闭顺序：先关闭 b，再关闭 a（与声明顺序相反）
```

如果 try 块和 close 都抛异常，close 的异常会被"抑制"（suppressed），通过 `getSuppressed()` 获取：

```java
try (MyResource r = new MyResource()) {
    throw new RuntimeException("try异常");
} catch (RuntimeException e) {
    System.out.println(e.getMessage());  // "try异常"
    Throwable[] suppressed = e.getSuppressed();
    // suppressed[0] 是 close 时抛出的异常
}
```

> **面试考点：try-with-resources 的原理？**
> 编译器会在 try 块的末尾自动生成 `finally` 块来调用资源的 `close()` 方法。资源必须实现 `AutoCloseable` 接口。JDK 9+ 还支持在 try 外部声明资源变量。

## 2.4 自定义异常设计规范

```java
// 自定义受检异常
public class BusinessException extends Exception {
    private final String code;

    public BusinessException(String code, String message) {
        super(message);
        this.code = code;
    }

    public BusinessException(String code, String message, Throwable cause) {
        super(message, cause);
        this.code = code;
    }

    public String getCode() { return code; }
}

// 自定义运行时异常（更常用）
public class BizRuntimeException extends RuntimeException {
    private final String code;

    public BizRuntimeException(String code, String message) {
        super(message);
        this.code = code;
    }

    public BizRuntimeException(String code, String message, Throwable cause) {
        super(message, cause);
        this.code = code;
    }

    public String getCode() { return code; }
}
```

**设计规范：**
- 异常类名以 `Exception` 结尾
- 包含错误码（code）和错误消息（message）
- 提供多个构造方法
- 业务异常通常继承 `RuntimeException`（避免过多的 try-catch）
- 全局异常处理器统一捕获并返回友好错误信息

## 2.5 异常处理最佳实践

**1. 不要捕获通用异常**

```java
// 不推荐
try {
    doSomething();
} catch (Exception e) {  // 太宽泛
    log.error("error", e);
}

// 推荐
try {
    doSomething();
} catch (FileNotFoundException e) {
    log.warn("文件未找到: {}", e.getMessage());
} catch (IOException e) {
    log.error("IO异常: {}", e.getMessage(), e);
}
```

**2. 不要用异常控制流程**

```java
// 不推荐：用异常控制流程
try {
    int result = list.get(index);
} catch (IndexOutOfBoundsException e) {
    // 处理越界
}

// 推荐：条件判断
if (index >= 0 && index < list.size()) {
    int result = list.get(index);
}
```

**3. 不要吞掉异常**

```java
// 不推荐：吞掉异常，出了问题无法排查
try {
    doSomething();
} catch (Exception e) {
    // 空的 catch 块
}

// 至少要记录日志
try {
    doSomething();
} catch (Exception e) {
    log.error("操作失败", e);
}
```

**4. 异常信息要明确**

```java
// 不推荐
throw new RuntimeException("error");

// 推荐
throw new BizRuntimeException("USER_NOT_FOUND", "用户不存在，userId=" + userId);
```

## 面试精选

### 1. Error 和 Exception 的区别？

Error 是程序无法处理的严重错误（如 OOM、StackOverflow），JVM 层面抛出，程序不应捕获；Exception 是程序可以处理的异常，分为受检异常（必须 try-catch 或 throws）和运行时异常（RuntimeException 及其子类，不强制处理）。

### 2. 受检异常和非受检异常的区别？

受检异常（Checked）继承自 Exception（不包括 RuntimeException），编译器强制要求处理（try-catch 或 throws 声明）；非受检异常（Unchecked）包括 RuntimeException 和 Error，编译器不强制处理。受检异常用于可预见的外部错误（如 IO 失败），非受检异常通常是编程错误（如空指针、数组越界）。

### 3. finally 块一定会执行吗？

不完全。以下情况 finally 不会执行：1）调用 `System.exit()`；2）JVM 崩溃；3）JVM 退出时（如所有非守护线程结束），守护线程的 finally 可能来不及执行。但在正常情况下，无论 try 块是否发生异常，finally 块都会执行（包括 try 中有 return 语句的情况——finally 在 return 之前执行）。

### 4. try-with-resources 的好处？原理是什么？

好处：自动关闭资源，代码简洁，避免资源泄露。原理：编译器在 try 块末尾自动生成 finally 块调用 `close()`。资源必须实现 `AutoCloseable`。多个资源按声明的反序关闭。如果 try 和 close 都抛异常，close 的异常会被作为 suppressed exception 附加到主异常上。

### 5. try 中有 return，finally 还会执行吗？

会。finally 在 return 语句之前执行。但注意：如果 finally 中也有 return，会覆盖 try 中的 return 值（不推荐这样做）。基本类型的 return 值在进入 finally 前已经确定，finally 无法改变；但如果 return 的是对象引用，finally 可以修改对象的属性。

### 6. 如何设计自定义异常？

通常继承 RuntimeException（避免强制处理）。包含错误码和错误消息，提供多个构造方法。业务异常统一命名（如 BizException）。配合全局异常处理器（@ControllerAdvice）统一捕获返回。避免设计过于复杂的异常继承体系，保持扁平。

### 7. 为什么阿里规约中禁止在 finally 中使用 return？

因为 finally 中的 return 会吞掉 try 或 catch 中的异常，导致异常被静默忽略，程序行为不可预期。编译器通常会对这种情况给出警告。
