## 3.1 Collection 体系全景图

```
Iterable
└── Collection
    ├── List（有序、可重复）
    │   ├── ArrayList
    │   ├── LinkedList
    │   └── Vector → Stack
    ├── Set（无序、不可重复）
    │   ├── HashSet → LinkedHashSet
    │   └── TreeSet
    └── Queue / Deque
        ├── PriorityQueue
        ├── ArrayDeque
        └── LinkedList（同时实现了 List 和 Deque）

Map（键值对，独立体系）
├── HashMap → LinkedHashMap
├── TreeMap
├── Hashtable → Properties
└── ConcurrentHashMap
```

## 3.2 List：ArrayList、LinkedList、Vector 对比

### 3.2.1 ArrayList 核心原理

```java
// JDK 8：默认空数组，首次 add 时扩容为 10
// JDK 7：默认直接创建长度为 10 的数组
transient Object[] elementData;
private int size;

// 扩容机制
private void grow(int minCapacity) {
    int oldCapacity = elementData.length;
    int newCapacity = oldCapacity + (oldCapacity >> 1); // 1.5 倍
    if (newCapacity < minCapacity)
        newCapacity = minCapacity;
    elementData = Arrays.copyOf(elementData, newCapacity);
}
```

**关键特点：**
- 底层 `Object[]` 数组，默认初始容量 10
- 扩容为原来的 1.5 倍（`oldCapacity + oldCapacity >> 1`）
- `add(E)` 平均 O(1)，最坏 O(n)（触发扩容时需要复制数组）
- `get(index)` O(1)（随机访问快）
- `add(index, E)` O(n)（需要移动元素）
- `remove(index)` O(n)（需要移动元素）
- **线程不安全**

### 3.2.2 LinkedList

```java
// 双向链表
private static class Node<E> {
    E item;
    Node<E> next;
    Node<E> prev;
}
```

- 底层双向链表
- `add(E)` O(1)（尾部插入）
- `get(index)` O(n)（需要遍历）
- `addFirst/addLast` O(1)
- `removeFirst/removeLast` O(1)
- 同时实现了 `List` 和 `Deque` 接口

### 3.2.3 三者对比

| 特性 | ArrayList | LinkedList | Vector |
|------|-----------|------------|--------|
| 底层结构 | 动态数组 | 双向链表 | 动态数组 |
| 随机访问 | O(1) | O(n) | O(1) |
| 插入/删除 | O(n) | O(1) | O(n) |
| 扩容 | 1.5 倍 | 无需 | 2 倍 |
| 线程安全 | 否 | 否 | 是（synchronized） |
| 推荐场景 | 读多写少 | 频繁插入删除 | 已不推荐使用 |

> **面试考点：ArrayList 和 LinkedList 怎么选？**
> 绝大多数场景用 ArrayList。只有在需要频繁在头部插入/删除、且不需要随机访问时才考虑 LinkedList。ArrayList 的 CPU 缓存友好性远优于 LinkedList（连续内存 vs 分散节点），实际测试中即使频繁插入删除，ArrayList 也常常比 LinkedList 快。

## 3.3 Set：HashSet、TreeSet、LinkedHashSet

### 3.3.1 HashSet

```java
// 底层就是 HashMap
private transient HashMap<E, Object> map;
private static final Object PRESENT = new Object(); // 所有 value 都是这个占位对象

public boolean add(E e) {
    return map.put(e, PRESENT) == null;
}
```

- 底层 `HashMap`，key 为元素，value 为固定的 `PRESENT` 对象
- 元素唯一性依赖 `hashCode()` 和 `equals()`
- 无序
- 允许 null

### 3.3.2 TreeSet

```java
// 底层 TreeMap（红黑树）
private transient NavigableMap<E, Object> m;
```

- 底层 `TreeMap`（红黑树）
- 元素有序（自然排序或自定义 Comparator）
- 不允许 null（需要比较）

### 3.3.3 LinkedHashSet

- 继承 HashSet，内部用 `LinkedHashMap` 实现
- 维护插入顺序
- 性能略低于 HashSet，但遍历顺序可预测

| 特性 | HashSet | TreeSet | LinkedHashSet |
|------|---------|---------|---------------|
| 底层 | HashMap | TreeMap | LinkedHashMap |
| 顺序 | 无序 | 排序 | 插入顺序 |
| null | 允许 1 个 | 不允许 | 允许 1 个 |
| 性能 | O(1) | O(log n) | O(1) |

## 3.4 Map：HashMap 核心原理（重点）

### 3.4.1 HashMap 底层结构

**JDK 7：数组 + 链表**

```
[0] → Entry → Entry → null
[1] → Entry → null
[2] → null
[3] → Entry → Entry → Entry → null
...
```

**JDK 8：数组 + 链表 + 红黑树**

```
[0] → Node → Node → null (链表，长度 < 8)
[1] → TreeNode (红黑树，链表长度 ≥ 8 且数组长度 ≥ 64)
[2] → null
[3] → Node → Node → Node → Node → Node → Node → Node → Node → TreeNode
...
```

### 3.4.2 核心参数

```java
// 默认初始容量：16（必须是 2 的幂）
static final int DEFAULT_INITIAL_CAPACITY = 1 << 4;

// 最大容量：2^30
static final int MAXIMUM_CAPACITY = 1 << 30;

// 默认负载因子：0.75
static final float DEFAULT_LOAD_FACTOR = 0.75f;

// 树化阈值：链表长度 ≥ 8 转红黑树
static final int TREEIFY_THRESHOLD = 8;

// 退化阈值：红黑树节点 ≤ 6 退化为链表
static final int UNTREEIFY_THRESHOLD = 6;

// 最小树化容量：数组长度 ≥ 64 才树化
static final int MIN_TREEIFY_CAPACITY = 64;
```

### 3.4.3 put 操作全流程（JDK 8）

```java
public V put(K key, V value) {
    return putVal(hash(key), key, value, false, true);
}

// 1. 计算 hash
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
    // 高 16 位与低 16 位异或，减少 hash 碰撞
}

final V putVal(int hash, K key, V value, boolean onlyIfAbsent, boolean evict) {
    // 2. 如果 table 为空，先 resize 初始化
    Node<K,V>[] tab; Node<K,V> p; int n, i;
    if ((tab = table) == null || (n = tab.length) == 0)
        n = (tab = resize()).length;

    // 3. 计算桶位置：(n - 1) & hash（等价于 hash % n，因为 n 是 2 的幂）
    if ((p = tab[i = (n - 1) & hash]) == null)
        tab[i] = newNode(hash, key, value, null);  // 桶为空，直接放入

    else {
        Node<K,V> e; K k;
        // 4. 桶的第一个节点就是要找的 key
        if (p.hash == hash && ((k = p.key) == key || (key != null && key.equals(k))))
            e = p;

        // 5. 如果是红黑树节点，走红黑树插入
        else if (p instanceof TreeNode)
            e = ((TreeNode<K,V>)p).putTreeVal(this, tab, hash, key, value);

        // 6. 链表遍历
        else {
            for (int binCount = 0; ; ++binCount) {
                if ((e = p.next) == null) {
                    p.next = newNode(hash, key, value, null);
                    // 链表长度 ≥ 8，尝试树化
                    if (binCount >= TREEIFY_THRESHOLD - 1)
                        treeifyBin(tab, hash);
                    break;
                }
                if (e.hash == hash && ((k = e.key) == key || (key != null && key.equals(k))))
                    break;  // 找到相同的 key
                p = e;
            }
        }

        // 7. key 已存在，覆盖旧值
        if (e != null) {
            V oldValue = e.value;
            if (!onlyIfAbsent || oldValue == null)
                e.value = value;
            afterNodeAccess(e);
            return oldValue;
        }
    }

    ++modCount;
    // 8. 检查是否需要扩容
    if (++size > threshold)
        resize();
    afterNodeInsertion(evict);
    return null;
}
```

### 3.4.4 为什么容量必须是 2 的幂？

```java
// 定位桶：(n - 1) & hash
// 当 n = 16 时，n - 1 = 15 = 0000_1111
// hash & 0000_1111 → 取 hash 的低 4 位 → 0~15
// 等价于 hash % 16，但位运算更快
```

2 的幂保证 `n - 1` 的二进制全是 1，与 hash 做 & 运算时能均匀分布到所有桶中。

## 3.5 Queue 与 Deque

```java
// Queue 接口
Queue<String> queue = new LinkedList<>();
queue.offer("a");    // 入队（推荐，队满返回 false）
queue.add("b");      // 入队（队满抛异常）
queue.poll();        // 出队（推荐，队空返回 null）
queue.remove();      // 出队（队空抛异常）
queue.peek();        // 查看队首（队空返回 null）
queue.element();     // 查看队首（队空抛异常）

// Deque 接口（双端队列，推荐用 ArrayDeque）
Deque<String> deque = new ArrayDeque<>();
deque.offerFirst("a");   // 头部入队
deque.offerLast("b");    // 尾部入队
deque.pollFirst();       // 头部出队
deque.pollLast();        // 尾部出队

// 优先队列（最小堆）
PriorityQueue<Integer> pq = new PriorityQueue<>();
pq.offer(3); pq.offer(1); pq.offer(2);
pq.poll(); // 1（最小值先出）
pq.poll(); // 2
pq.poll(); // 3
```

## 3.7 集合选型原则

```
需要键值对？
├── 是 → Map
│   ├── 需要排序？→ TreeMap
│   ├── 需要插入顺序？→ LinkedHashMap
│   ├── 线程安全？→ ConcurrentHashMap
│   └── 其他 → HashMap
│
└── 否 → Collection
    ├── 不允许重复？→ Set
    │   ├── 需要排序？→ TreeSet
    │   ├── 需要插入顺序？→ LinkedHashSet
    │   └── 其他 → HashSet
    │
    ├── 需要队列？→ Queue / Deque → ArrayDeque
    │
    └── 允许重复？→ List
        ├── 随机访问多？→ ArrayList
        └── 插入删除多？→ LinkedList（但通常 ArrayList 更优）
```

## 面试精选

### 1. HashMap 的底层原理？JDK 7 和 8 有什么区别？

JDK 7：数组 + 链表，使用头插法，并发扩容可能形成环形链表导致死循环。JDK 8：数组 + 链表 + 红黑树，使用尾插法避免环形链表，链表长度 ≥ 8 且数组长度 ≥ 64 时转红黑树（O(n) → O(log n)）。hash 函数优化为高 16 位异或低 16 位。扩容时元素要么在原位置，要么在原位置 + 旧容量处。

### 2. HashMap 为什么容量是 2 的幂？hash 函数怎么设计的？

容量为 2 的幂时，`n - 1` 的二进制全是 1，`(n - 1) & hash` 等价于 `hash % n`，位运算更快且分布均匀。hash 函数：`(h = key.hashCode()) ^ (h >>> 16)`，将高 16 位混入低 16 位，减少哈希碰撞。

### 3. HashMap 什么时候会扩容？扩容过程？

当 `size > capacity × loadFactor` 时触发扩容（默认 loadFactor = 0.75）。新容量 = 旧容量 × 2。JDK 8 优化了扩容过程：通过 `hash & oldCap` 判断元素在新数组中的位置，要么在原位置，要么在原位置 + 旧容量处，无需重新计算 hash。

### 4. HashMap 的 key 可以为 null 吗？可以为哪些类型？

可以为 null（hash 值为 0，放在数组第一个位置），但最多只能有一个 null key。key 的类型需要正确重写 `hashCode()` 和 `equals()` 方法，否则可能出现逻辑重复的 key。推荐使用 String、Integer 等不可变类作为 key。

### 5. ConcurrentHashMap 的原理？

JDK 7：Segment 分段锁（默认 16 个），并发度受限于 Segment 数量。JDK 8：放弃分段锁，使用 CAS + synchronized（锁粒度到桶级别），Node 数组 + 链表/红黑树，与 HashMap 结构类似但线程安全。key 和 value 都不允许为 null。

### 6. ArrayList 和 LinkedList 的区别？

ArrayList 底层动态数组，随机访问 O(1)，插入删除 O(n)，CPU 缓存友好；LinkedList 底层双向链表，随机访问 O(n)，头尾操作 O(1)，内存不连续。实际开发中 ArrayList 几乎总是更优的选择，因为 CPU 缓存命中率高，且数组操作的实际开销往往低于链表的内存分配和指针跳转。

### 7. HashMap 和 Hashtable 的区别？

1）HashMap 线程不安全，Hashtable 方法加 synchronized 线程安全但性能差；2）HashMap 允许 null key/value，Hashtable 不允许；3）HashMap 初始容量 16，Hashtable 初始容量 11；4）HashMap 扩容 2 倍，Hashtable 扩容 2n+1；5）推荐用 ConcurrentHashMap 替代 Hashtable。

### 8. 为什么链表长度为 8 时转红黑树？

泊松分布下，链表长度达到 8 的概率约为 0.00000006，极小概率事件。选择 8 是时间和空间的权衡：链表长度较短时遍历很快，树化需要额外的内存开销（TreeNode 是 Node 的两倍大小），只有在极端哈希碰撞时才值得树化。同时退化阈值设为 6，避免在 8 附近频繁树化/退化。
