## 27.1 Docker 基础

```dockerfile
# Java 应用 Dockerfile 示例
FROM eclipse-temurin:21-jre-alpine
WORKDIR /app
COPY target/app.jar app.jar
EXPOSE 8080
ENV JAVA_OPTS="-Xms512m -Xmx512m"
ENTRYPOINT ["sh", "-c", "java $JAVA_OPTS -jar app.jar"]
```

```bash
# 常用命令
docker build -t myapp:1.0 .
docker run -d -p 8080:8080 --name myapp myapp:1.0
docker logs -f myapp
docker exec -it myapp /bin/sh
docker-compose up -d
```

**Docker 核心概念：**
- **镜像（Image）**：只读模板，分层存储
- **容器（Container）**：镜像的运行实例
- **Dockerfile**：构建镜像的脚本
- **Docker Compose**：多容器编排

## 27.2 Kubernetes 核心概念

```
K8s 架构：
├── Master（控制面）
│   ├── API Server：集群入口
│   ├── Scheduler：Pod 调度
│   ├── Controller Manager：状态管理
│   └── etcd：集群状态存储
└── Node（工作节点）
    ├── kubelet：节点代理
    ├── kube-proxy：网络代理
    └── Container Runtime：容器运行时
```

**核心资源：**

```yaml
# Deployment：无状态应用部署
apiVersion: apps/v1
kind: Deployment
metadata:
  name: user-service
spec:
  replicas: 3
  selector:
    matchLabels:
      app: user-service
  template:
    metadata:
      labels:
        app: user-service
    spec:
      containers:
      - name: user-service
        image: user-service:1.0
        ports:
        - containerPort: 8080
        resources:
          requests:
            memory: "512Mi"
            cpu: "500m"
          limits:
            memory: "1Gi"
            cpu: "1000m"
---
# Service：服务暴露
apiVersion: v1
kind: Service
metadata:
  name: user-service
spec:
  selector:
    app: user-service
  ports:
  - port: 80
    targetPort: 8080
  type: ClusterIP
```

| 资源 | 说明 |
|------|------|
| Pod | 最小部署单元，一个或多个容器 |
| Deployment | 管理 Pod 副本、滚动更新 |
| Service | 服务发现和负载均衡 |
| Ingress | HTTP 路由（域名→Service） |
| ConfigMap | 配置管理 |
| Secret | 敏感信息管理 |

## 27.3 云原生 12 要素

```
1. 基准代码：一份代码多次部署
2. 依赖：显式声明依赖
3. 配置：环境变量存储配置
4. 后端服务：视后端服务为附加资源
5. 构建/发布/运行：严格分离

11. 日志：视日志为事件流
12. 管理进程：后台管理任务
```

## 面试精选

### 1. Docker 和虚拟机的区别？

Docker 容器共享宿主机内核，启动快（秒级），资源占用少。虚拟机有独立内核，启动慢（分钟级），资源占用大。容器隔离性不如虚拟机，但性能更好。

### 2. K8s 的核心概念？

Pod（最小部署单元）、Deployment（管理副本和滚动更新）、Service（服务发现和负载均衡）、Ingress（HTTP路由）。Master 负责调度和管理，Node 负责运行容器。

### 3. 怎么实现零停机部署？

K8s 滚动更新（Rolling Update）：逐步替换旧 Pod，设置 maxSurge 和 maxUnavailable。配合 readinessProbe（就绪探针）确保新 Pod 就绪后再接收流量。优雅终止：preStop hook + SIGTERM 处理。
