## 25.1 秒杀系统设计

```
核心挑战：瞬时高并发、超卖问题、数据一致性

架构设计：
前端：
├── 页面静态化（CDN）
├── 按钮防重（倒计时 + 禁用）
└── 请求削峰（答题/验证码）

网关层：
├── 限流（令牌桶，只放行 10% 请求）
├── 鉴权（Token 校验）
└── 请求过滤（非法请求直接拒绝）

服务层：
├── Redis 预减库存（DECR 原子操作）
├── 内存标记（已售罄标志位）
├── 异步下单（MQ 削峰）
└── 订单超时取消（延迟队列）

数据层：
├── 库存扣减（乐观锁：WHERE stock > 0）
└── 订单表（唯一索引防重复下单）
```

```java
// 秒杀核心逻辑（Lua 脚本保证原子性）
public boolean seckill(Long userId, Long itemId) {
    // 1. 内存标记，已售罄直接返回
    if (soldOutMap.get(itemId)) return false;

    // 2. Lua 脚本：检查库存 > 0 后原子扣减
    String luaScript = """
        if tonumber(redis.call('GET', KEYS[1])) > 0 then
            redis.call('DECR', KEYS[1])
            return 1
        else
            return 0
        end
        """;
    Long result = redisTemplate.execute(
        new DefaultRedisScript<>(luaScript, Long.class),
        List.of("stock:" + itemId));

    if (result == 0) {
        soldOutMap.put(itemId, true);
        return false;
    }

    // 3. 异步下单
    rabbitTemplate.convertAndSend("seckill.queue", new SeckillMessage(userId, itemId));
    return true;
}
```

## 25.2 短链系统设计

```
长链接 → 生成短码 → 存储映射关系 → 短链访问 → 302 重定向

短码生成：
- 自增 ID + Base62 编码（0-9, a-z, A-Z）
- 雪花算法 ID + Base62
- MurmurHash + 冲突处理

存储：
- MySQL：id, short_code, long_url, create_time
- Redis：short_code → long_url（缓存热点短链）

跳转：
- 302 重定向（可统计点击量）
- 301 永久重定向（浏览器缓存，无法统计）
```

## 25.3 Feed 流系统设计

```
推模式（Push）：发布时推送到所有粉丝的收件箱
- 优点：读取快（直接查收件箱）
- 缺点：大V发布时写扩散严重
- 适合：粉丝少的普通用户

拉模式（Pull）：读取时实时拉取关注人的动态
- 优点：写入快
- 缺点：读取慢（需要聚合多个关注人的数据）
- 适合：粉丝多的大V

推拉结合（推荐）：
- 普通用户发帖 → Push 到粉丝收件箱
- 大V发帖 → 不 Push，粉丝读取时实时 Pull
- 读取时：收件箱（Push）+ 关注的大V（Pull）合并排序
```

## 面试精选

### 1. 秒杀系统怎么设计？

三层防护：前端限流（验证码/答题）→ 网关限流（令牌桶）→ 服务层（Redis预减库存+内存标记+MQ异步下单）。数据库乐观锁防超卖。核心思想：尽量把请求拦截在上游，减少打到数据库的流量。

### 2. 短链系统怎么设计？

自增ID+Base62生成短码，MySQL存储映射关系，Redis缓存热点短链，302重定向实现跳转。注意短码冲突处理和分布式ID生成。

### 3. Feed 流推拉模式怎么选？

普通用户用推模式（写扩散），大V用拉模式（读扩散），推拉结合取长补短。读取时合并收件箱（Push数据）和关注的大V（Pull数据），按时间排序。
