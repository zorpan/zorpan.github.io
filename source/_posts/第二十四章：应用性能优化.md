## 24.1 代码层面优化

}
// 推荐：复用对象
SimpleDateFormat sdf = new SimpleDateFormat("yyyy-MM-dd");

// 2. 避免 N+1 查询
// 不推荐：循环查数据库
for (Order order : orders) {
    User user = userDao.findById(order.getUserId());  // N 次查询

List<Long> userIds = orders.stream().map(Order::getUserId).collect(toList());
Map<Long, User> userMap = userDao.findByIds(userIds).stream()
    .collect(Collectors.toMap(User::getId, u -> u));

// 3. 懒加载
// 使用 @Lazy 延迟初始化 Bean
// 使用 Stream 的延迟执行特性

// 4. 使用 StringBuilder 拼接字符串
// 5. 集合初始化时指定容量

## 24.2 数据库性能调优

```sql
-- 1. 慢 SQL 优化
EXPLAIN SELECT * FROM user WHERE name = 'Tom';
-- type=ALL → 全表扫描，需要加索引
-- Using filesort → 需要优化 ORDER BY
-- Using temporary → 需要优化 GROUP BY

-- 不推荐
INSERT INTO user VALUES (1, 'Tom');
INSERT INTO user VALUES (2, 'Jerry');

INSERT INTO user VALUES (1, 'Tom'), (2, 'Jerry');

-- 3. 连接池配置
-- HikariCP 推荐配置

## 24.3 缓存优化策略

```
热点 Key 处理：
├── 本地缓存（Caffeine）缓存热点数据
├── Redis Key 分片（key_1, key_2, ... key_N）
└── 读写分离（主写从读）

缓存一致性：
├── Cache Aside：先更新数据库，再删除缓存
├── 延迟双删：更新 DB → 删缓存 → 延迟再删缓存
└── 监听 Binlog：通过 Canal 监听 MySQL 变更同步到 Redis

## 面试精选

### 1. 怎么做性能优化？

四个层面：代码（减少对象创建、避免N+1、懒加载）、数据库（索引优化、批量操作、连接池配置）、缓存（多级缓存、热点Key处理）、JVM（堆大小调优、GC选择）。优先解决瓶颈最大的环节。

### 2. 大表查询怎么优化？

索引优化（覆盖索引、联合索引）、分页优化（延迟关联、游标分页）、读写分离、分库分表、缓存热点数据。

### 3. 线程池怎么调优？

CPU密集型：核心线程数=CPU核心数+1。IO密集型：核心线程数=CPU核心数*2。通用公式：CPU核心数*(1+IO等待时间/CPU计算时间)。生产通过压测确定最优值。拒绝策略推荐 CallerRunsPolicy。
