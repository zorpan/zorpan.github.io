## 23.1 高可用设计原则

```
冗余：多副本、多实例、多机房
限流：控制请求速率，保护系统不被打垮
熔断：当下游服务异常时快速失败，避免级联故障
降级：核心功能优先保障，非核心功能降级处理
```

## 23.2 限流算法

| 算法 | 原理 | 特点 |
|------|------|------|
| 计数器 | 固定窗口计数 | 简单，窗口临界突刺 |
| 滑动窗口 | 滑动时间窗口计数 | 解决临界突刺 |
| 漏桶 | 固定速率流出 | 平滑流量，不能应对突发 |
| 令牌桶 | 固定速率放令牌 | 平滑流量，允许一定突发 |

```java
// Guava RateLimiter（基于 SmoothBursty 算法，漏桶变体，允许突发）
RateLimiter limiter = RateLimiter.create(100);  // 每秒 100 个请求
if (limiter.tryAcquire()) {
    // 处理请求
} else {
    // 限流
}
```

## 23.3 服务容错与重试策略

```java
// Spring Retry
@Retryable(
    value = {RemoteAccessException.class},
    maxAttempts = 3,
    backoff = @Backoff(delay = 1000, multiplier = 2)  // 退避策略
)
public User getUser(Long id) {
    return userClient.getUser(id);
}

@Recover
public User getUserRecover(RemoteAccessException e, Long id) {
    return User.builder().id(id).name("降级用户").build();
}
```

## 23.4 灰度发布与蓝绿部署

```
蓝绿部署：
├── 蓝环境（当前版本）→ 全量流量
└── 绿环境（新版本）→ 测试通过后切换流量

灰度发布（金丝雀发布）：
├── 90% 流量 → 旧版本
└── 10% 流量 → 新版本（逐步扩大比例）

滚动发布：
逐批替换实例，保证服务始终可用
```

## 面试精选

### 1. 限流算法有哪些？怎么选？

计数器（简单）、滑动窗口（精确）、漏桶（平滑）、令牌桶（允许突发）。Sentinel 默认滑动窗口，Guava RateLimiter 令牌桶。大多数场景选滑动窗口或令牌桶。

### 2. 熔断和降级的区别？

熔断是自动触发的保护机制（当下游错误率超阈值时自动切断调用），降级是主动的策略（核心功能保障，非核心功能降级）。熔断后通常触发降级逻辑返回兜底数据。

### 3. 怎么设计高可用系统？

冗余（多实例多副本）、限流（保护系统容量）、熔断（防止级联故障）、降级（保障核心功能）、超时控制、重试机制、健康检查、自动扩缩容。
