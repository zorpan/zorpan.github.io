## 7.1 设计模式概览

设计模式分为三大类：

```
创建型（5 种）— 对象创建机制
├── 单例模式 Singleton
├── 工厂方法模式 Factory Method
├── 抽象工厂模式 Abstract Factory
├── 建造者模式 Builder
└── 原型模式 Prototype

结构型（7 种）— 类与对象的组合
├── 适配器模式 Adapter
├── 桥接模式 Bridge
├── 组合模式 Composite
├── 装饰器模式 Decorator
├── 外观模式 Facade
├── 享元模式 Flyweight
└── 代理模式 Proxy

行为型（11 种）— 对象间的通信
├── 责任链模式 Chain of Responsibility
├── 命令模式 Command
├── 迭代器模式 Iterator
├── 中介者模式 Mediator
├── 观察者模式 Observer
├── 状态模式 State
├── 策略模式 Strategy
├── 模板方法模式 Template Method
├── 备忘录模式 Memento
├── 访问者模式 Visitor
└── 解释器模式 Interpreter
```

## 7.2 常用设计模式详解

### 7.2.1 单例模式（Singleton）

保证一个类只有一个实例，提供全局访问点。

**枚举实现（推荐）：**

```java
public enum Singleton {
    INSTANCE;
    public void doSomething() { }
}
// 天然线程安全、防反射攻击、支持序列化
```

**双重检查锁（DCL）：**

```java
public class Singleton {
    private static volatile Singleton instance;

    private Singleton() {}

    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

**静态内部类（推荐）：**

```java
public class Singleton {
    private Singleton() {}

    private static class Holder {
        private static final Singleton INSTANCE = new Singleton();
    }

    public static Singleton getInstance() {
        return Holder.INSTANCE;
    }
}
// 利用类加载机制保证线程安全，懒加载
```

### 7.2.2 工厂方法模式（Factory Method）

定义创建对象的接口，让子类决定实例化哪个类。

```java
// 简单工厂
public class LoggerFactory {
    public static Logger getLogger(String type) {
        return switch (type) {
            case "file" -> new FileLogger();
            case "console" -> new ConsoleLogger();
            default -> throw new IllegalArgumentException();
        };
    }
}

// 工厂方法（符合开闭原则）
public abstract class LoggerFactory {
    public abstract Logger createLogger();
}

public class FileLoggerFactory extends LoggerFactory {
    @Override
    public Logger createLogger() { return new FileLogger(); }
}
```

### 7.2.3 策略模式（Strategy）

定义一系列算法，将每个算法封装起来，使它们可以互相替换。

```java
// 策略接口
public interface SortStrategy<T extends Comparable<T>> {
    void sort(List<T> list);
}

// 具体策略
public class QuickSort<T extends Comparable<T>> implements SortStrategy<T> {
    @Override
    public void sort(List<T> list) { /* 快速排序实现 */ }
}

public class MergeSort<T extends Comparable<T>> implements SortStrategy<T> {
    @Override
    public void sort(List<T> list) { /* 归并排序实现 */ }
}

// 上下文
public class Sorter<T extends Comparable<T>> {
    private SortStrategy<T> strategy;

    public Sorter(SortStrategy<T> strategy) {
        this.strategy = strategy;
    }

    public void sort(List<T> list) {
        strategy.sort(list);
    }
}
```

**Java 中的应用：** `Comparator` 就是策略模式，`Collections.sort(list, comparator)` 可以传入不同的比较策略。

### 7.2.4 观察者模式（Observer）

定义一对多的依赖关系，当一个对象状态改变时，所有依赖它的对象都会得到通知。

```java
// Java 内置支持
// 方式1：自定义实现
public interface EventListener {
    void onEvent(String event);
}

public class EventBus {
    private final Map<String, List<EventListener>> listeners = new HashMap<>();

    public void subscribe(String event, EventListener listener) {
        listeners.computeIfAbsent(event, k -> new ArrayList<>()).add(listener);
    }

    public void publish(String event) {
        listeners.getOrDefault(event, List.of())
            .forEach(l -> l.onEvent(event));
    }
}

// 方式2：Spring ApplicationEvent
@Component
public class OrderEventListener {
    @EventListener
    public void onOrderCreated(OrderCreatedEvent event) {
        // 处理订单创建事件
    }
}
```

### 7.2.5 代理模式（Proxy）

为其他对象提供代理以控制对目标对象的访问。

```java
// 静态代理
public interface UserService {
    User findById(Long id);
}

public class UserServiceImpl implements UserService {
    @Override
    public User findById(Long id) { return userDao.findById(id); }
}

public class UserServiceProxy implements UserService {
    private final UserService target;

    public UserServiceProxy(UserService target) {
        this.target = target;
    }

    @Override
    public User findById(Long id) {
        log.info("before findById, id={}", id);
        User user = target.findById(id);
        log.info("after findById");
        return user;
    }
}

// JDK 动态代理（目标类必须实现接口）
UserService proxy = (UserService) Proxy.newProxyInstance(
    UserService.class.getClassLoader(),
    new Class[]{UserService.class},
    (obj, method, args) -> {
        log.info("before {}", method.getName());
        Object result = method.invoke(target, args);
        log.info("after {}", method.getName());
        return result;
    }
);

// CGLIB 动态代理（不需要接口，通过继承实现代理）
// Spring AOP 默认策略：有接口用 JDK 代理，无接口用 CGLIB
```

### 7.2.6 装饰器模式（Decorator）

动态地给对象添加额外功能，IO 流的设计就是经典案例。

```java
// 基础接口
public interface DataSource {
    void writeData(String data);
    String readData();
}

// 基础实现
public class FileDataSource implements DataSource {
    private String filename;
    @Override
    public void writeData(String data) { /* 写入文件 */ }
    @Override
    public String readData() { /* 从文件读取 */ }
}

// 装饰器：加密
public class EncryptionDecorator implements DataSource {
    private DataSource wrapped;
    public EncryptionDecorator(DataSource source) { this.wrapped = source; }

    @Override
    public void writeData(String data) {
        wrapped.writeData(encrypt(data));  // 加密后写入
    }

    @Override
    public String readData() {
        return decrypt(wrapped.readData());  // 读取后解密
    }
}

// 使用：层层装饰
DataSource source = new EncryptionDecorator(
    new CompressionDecorator(
        new FileDataSource("data.txt")));
```

### 7.2.7 模板方法模式（Template Method）

定义算法骨架，将某些步骤延迟到子类实现。

```java
public abstract class AbstractGame {
    // 模板方法：定义算法骨架
    public final void play() {
        initialize();
        startPlay();
        endPlay();
    }

    protected abstract void initialize();
    protected abstract void startPlay();
    protected abstract void endPlay();
}

public class FootballGame extends AbstractGame {
    @Override
    protected void initialize() { System.out.println("初始化足球场"); }
    @Override
    protected void startPlay() { System.out.println("开始足球比赛"); }
    @Override
    protected void endPlay() { System.out.println("足球比赛结束"); }
}
```

**Java 中的应用：** `AbstractList`、`AbstractMap`、`HttpServlet.service()` → `doGet()`/`doPost()`。

### 7.2.8 建造者模式（Builder）

将复杂对象的构建与表示分离，适合参数很多的场景。

```java
public class HttpRequest {
    private final String url;
    private final String method;
    private final Map<String, String> headers;
    private final String body;

    private HttpRequest(Builder builder) {
        this.url = builder.url;
        this.method = builder.method;
        this.headers = builder.headers;
        this.body = builder.body;
    }

    public static class Builder {
        private String url;
        private String method = "GET";
        private Map<String, String> headers = new HashMap<>();
        private String body;

        public Builder(String url) { this.url = url; }
        public Builder method(String method) { this.method = method; return this; }
        public Builder header(String key, String value) { headers.put(key, value); return this; }
        public Builder body(String body) { this.body = body; return this; }
        public HttpRequest build() { return new HttpRequest(this); }
    }
}

// 使用
HttpRequest request = new HttpRequest.Builder("https://api.example.com")
    .method("POST")
    .header("Content-Type", "application/json")
    .body("{\"name\":\"test\"}")
    .build();
```

## 7.3 SOLID 原则与实战应用

### S — 单一职责原则（SRP）

一个类只有一个引起变化的原因。

```java
// 违反 SRP：一个类做了太多事
public class User {
    void saveToDatabase() { }
    void sendEmail() { }
    void generateReport() { }
}

// 遵循 SRP：职责分离
public class User { }
public class UserRepository { void save(User user) { } }
public class EmailService { void sendEmail(User user) { } }
public class ReportGenerator { void generate(User user) { } }
```

### O — 开闭原则（OCP）

对扩展开放，对修改关闭。通过抽象和多态实现。

```java
// 违反 OCP：每加一种形状都要修改 AreaCalculator
public class AreaCalculator {
    public double calculate(Object shape) {
        if (shape instanceof Circle) { /* ... */ }
        else if (shape instanceof Rectangle) { /* ... */ }
    }
}

// 遵循 OCP：新增形状只需新增类
public interface Shape { double area(); }
public class Circle implements Shape { public double area() { return Math.PI * r * r; } }
public class Rectangle implements Shape { public double area() { return width * height; } }
// 新增 Triangle 只需实现 Shape，无需修改已有代码
```

### L — 里氏替换原则（LSP）

子类必须能够替换父类，且不改变程序的正确性。

```java
// 违反 LSP：正方形不是长方形的合理子类
class Rectangle {
    protected int width, height;
    void setWidth(int w) { width = w; }
    void setHeight(int h) { height = h; }
    int area() { return width * height; }
}

class Square extends Rectangle {
    @Override
    void setWidth(int w) { width = height = w; }  // 改变了父类行为
    @Override
    void setHeight(int h) { width = height = h; }
}
// 调用方期望设置宽高独立，但 Square 改变了语义
```

### I — 接口隔离原则（ISP）

客户端不应该被迫依赖它不需要的接口。

```java
// 违反 ISP：一个臃肿的接口
public interface Animal {
    void eat();
    void swim();
    void fly();  // 不是所有动物都会飞
}

// 遵循 ISP：拆分为小接口
public interface Eatable { void eat(); }
public interface Swimmable { void swim(); }
public interface Flyable { void fly(); }

public class Duck implements Eatable, Swimmable, Flyable { }
public class Fish implements Eatable, Swimmable { }
```

### D — 依赖倒置原则（DIP）

高层模块不应依赖低层模块，两者都应依赖抽象。

```java
// 违反 DIP：高层直接依赖低层实现
public class OrderService {
    private MySQLDatabase database = new MySQLDatabase();  // 直接依赖具体类
}

// 遵循 DIP：依赖接口
public class OrderService {
    private final Database database;  // 依赖抽象

    public OrderService(Database database) {  // 构造注入
        this.database = database;
    }
}
// 可以替换为 MySQL、PostgreSQL、MongoDB 等任意实现
```

## 7.4 DRY、KISS、YAGNI 编程原则

**DRY（Don't Repeat Yourself）**
不要重复自己。相同的逻辑只在一个地方定义，通过方法提取、继承、组合等方式消除重复。

**KISS（Keep It Simple, Stupid）**
保持简单。代码应该尽可能简单易懂，避免过度设计和炫技。

**YAGNI（You Ain't Gonna Need It）**
你不会需要它。不要为未来可能的需求提前写代码，只实现当前需要的功能。

## 7.5 领域驱动设计（DDD）入门

### 核心概念

```
战略设计：
├── 领域（Domain）：业务问题域
├── 子域（Subdomain）：核心域、支撑域、通用域
├── 限界上下文（Bounded Context）：明确的边界
└── 上下文映射（Context Map）：上下文之间的关系

战术设计：
├── 实体（Entity）：有唯一标识，如 Order、User
├── 值对象（Value Object）：无唯一标识，如 Money、Address
├── 聚合（Aggregate）：一组相关对象的集合，有聚合根
├── 聚合根（Aggregate Root）：聚合的入口，如 Order（包含 OrderItem）
├── 仓储（Repository）：聚合的持久化接口
├── 领域服务（Domain Service）：不属于任何实体的业务逻辑
└── 领域事件（Domain Event）：领域中发生的重要事件
```

### 实体 vs 值对象

```java
// 实体：有唯一标识，状态可变
public class Order {
    private OrderId id;       // 唯一标识
    private OrderStatus status;
    public void cancel() { this.status = OrderStatus.CANCELLED; }
}

// 值对象：无唯一标识，不可变，通过属性判断相等性
public record Money(BigDecimal amount, Currency currency) {
    public Money add(Money other) {
        if (!this.currency.equals(other.currency))
            throw new IllegalArgumentException();
        return new Money(this.amount.add(other.amount), currency);
    }
}
```

### 聚合设计原则

- 聚合根是唯一对外暴露的入口
- 聚合内保证强一致性，聚合间保证最终一致性
- 聚合应尽量小，一个事务只修改一个聚合

## 面试精选

### 1. 常用的设计模式有哪些？请举例说明。

创建型：单例（枚举实现、Spring Bean 默认单例）、工厂方法（BeanFactory）、建造者（StringBuilder、Lombok @Builder）。结构型：代理（Spring AOP、MyBatis Mapper）、装饰器（IO 流、Collections.synchronizedXxx）、适配器（HandlerAdapter）。行为型：策略（Comparator、ThreadPoolExecutor 拒绝策略）、观察者（Spring Event、MQ）、模板方法（AbstractList、HttpServlet）。

### 2. 代理模式和装饰器模式的区别？

代理模式关注控制对象访问（如添加权限校验、懒加载），代理对象通常不改变接口行为；装饰器模式关注动态添加功能（如加密、压缩），装饰器通常保持接口不变但增强行为。代理通常一对一，装饰器可以层层嵌套。Spring AOP 是代理模式，IO 流是装饰器模式。

### 3. 策略模式和工厂模式的区别？

工厂模式关注对象创建（"创建什么"），策略模式关注行为选择（"怎么做"）。工厂返回的是对象，策略返回的是算法。实际开发中两者经常结合使用：用工厂创建不同的策略实例，再注入到上下文中使用。

### 4. 什么是开闭原则？怎么实现？

对扩展开放、对修改关闭。新增功能时不修改已有代码。实现方式：通过接口/抽象类定义契约，通过多态和依赖注入实现扩展。Spring 中大量使用（如 BeanPostProcessor 扩展点、HandlerMapping 扩展）。

### 5. Spring 中用到了哪些设计模式？

工厂模式（BeanFactory）、单例模式（Bean 默认作用域）、代理模式（AOP）、模板方法（JdbcTemplate、RestTemplate）、观察者模式（ApplicationEvent）、策略模式（Resource 接口）、适配器模式（HandlerAdapter）、装饰器模式（BeanWrapper）等。

### 6. 什么是 DDD？和传统三层架构的区别？

DDD 以领域模型为核心，先理解业务再设计系统，关注限界上下文和聚合边界。传统三层架构按技术分层（Controller-Service-Dao），业务逻辑散落在 Service 层。DDD 将核心逻辑封装在领域模型中，贫血模型 → 充血模型，更适合复杂业务场景。

### 7. 单例模式有几种实现方式？推荐哪种？

五种：饿汉式、懒汉式（synchronized）、双重检查锁（DCL）、静态内部类、枚举。推荐枚举实现：天然线程安全、防反射攻击、支持序列化、代码最简洁。次选静态内部类：懒加载、线程安全、无锁性能好。
