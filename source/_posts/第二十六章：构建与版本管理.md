## 26.1 Maven 核心

### 依赖管理

```xml
<!-- 依赖范围 -->
<dependency>
    <groupId>org.springframework</groupId>
    <artifactId>spring-core</artifactId>
    <version>6.1.0</version>
    <scope>compile</scope>  <!-- compile|provided|runtime|test -->
</dependency>
```

| scope | 编译 | 测试 | 运行 | 打包 |
|-------|------|------|------|------|
| compile | ✅ | ✅ | ✅ | ✅ |
| provided | ✅ | ✅ | ❌ | ❌ |
| runtime | ❌ | ✅ | ✅ | ✅ |
| test | ❌ | ✅ | ❌ | ❌ |

### 依赖冲突解决

```
Maven 依赖调解规则：
1. 最短路径优先：A → B → C vs A → C，选后者
2. 先声明优先：同一 pom 中先声明的优先
3. 排除依赖：<exclusions> 排除冲突版本
4. 版本锁定：<dependencyManagement> 统一管理版本
```

### 生命周期

```
clean → validate → compile → test → package → verify → install → deploy

常用命令：
mvn clean package -DskipTests    # 跳过测试打包
mvn dependency:tree              # 查看依赖树
mvn versions:display-dependency-updates  # 检查依赖更新
```

## 26.2 Git 工作流

```
Git Flow（经典）：
├── main：生产环境代码
├── develop：开发分支
├── feature/*：功能分支
├── release/*：发布准备
└── hotfix/*：紧急修复

Trunk-Based（推荐）：
├── main：主干，始终可部署
└── feature/*：短生命周期功能分支（1-2 天合并）
```

**Git 常用命令：**
```bash
git rebase -i HEAD~3      # 交互式变基，合并提交
git cherry-pick <commit>  # 摘取特定提交
git stash / git stash pop # 暂存/恢复工作区
git bisect                # 二分查找 bug
```

## 面试精选

### 1. Maven 依赖冲突怎么解决？

最短路径优先、先声明优先、exclusion 排除冲突版本、dependencyManagement 锁定版本。mvn dependency:tree 查看依赖树定位冲突。

### 2. Git Flow 和 Trunk-Based 的区别？

Git Flow 分支多、流程规范但复杂，适合发版周期长的项目。Trunk-Based 主干开发、短生命周期分支，适合持续部署的互联网团队。推荐 Trunk-Based + CI/CD。
