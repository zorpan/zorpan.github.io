面试考点：Error 和 Exception 的区别？
Error 是程序无法处理的严重错误（如 OOM），通常由 JVM 抛出，程序不应捕获；Exception 是程序可以处理的异常，分为受检异常（必须处理）和运行时异常（可处理可不处理）。

编译器会在 try 块的末尾自动生成 finally 块来调用资源的 close() 方法。资源必须实现 AutoCloseable 接口。JDK 9+ 还支持在 try 外部声明资源变量。

2.4 自定义异常设计规范

设计规范：

  • 异常类名以 Exception 结尾
  • 包含错误码（code）和错误消息（message）
  • 提供多个构造方法
  • 业务异常通常继承 RuntimeException（避免过多的 try-catch）
  • 全局异常处理器统一捕获并返回友好错误信息

面试精选

1. Error 和 Exception 的区别？

Error 是程序无法处理的严重错误（如 OOM、StackOverflow），JVM 层面抛出，程序不应捕获；Exception 是程序可以处理的异常，分为受检异常（必须 try-catch 或 throws）和运行时异常（RuntimeException 及其子类，不强制处理）。

2. 受检异常和非受检异常的区别？

受检异常（Checked）继承自 Exception（不包括 RuntimeException），编译器强制要求处理（try-catch 或 throws 声明）；非受检异常（Unchecked）包括 RuntimeException 和 Error，编译器不强制处理。受检异常用于可预见的外部错误（如 IO 失败），非受检异常通常是编程错误（如空指针、数组越界）。

3. finally 块一定会执行吗？

不完全。以下情况 finally 不会执行：1）调用 System.exit()；2）JVM 崩溃；3）JVM 退出时（如所有非守护线程结束），守护线程的 finally 可能来不及执行。但在正常情况下，无论 try 块是否发生异常，finally 块都会执行（包括 try 中有 return 语句的情况——finally 在 return 之前执行）。

4. try-with-resources 的好处？原理是什么？

好处：自动关闭资源，代码简洁，避免资源泄露。原理：编译器在 try 块末尾自动生成 finally 块调用 close()。资源必须实现 AutoCloseable。多个资源按声明的反序关闭。如果 try 和 close 都抛异常，close 的异常会被作为 suppressed exception 附加到主异常上。

5. try 中有 return，finally 还会执行吗？

会。finally 在 return 语句之前执行。但注意：如果 finally 中也有 return，会覆盖 try 中的 return 值（不推荐这样做）。基本类型的 return 值在进入 finally 前已经确定，finally 无法改变；但如果 return 的是对象引用，finally 可以修改对象的属性。

6. 如何设计自定义异常？

通常继承 RuntimeException（避免强制处理）。包含错误码和错误消息，提供多个构造方法。业务异常统一命名（如 BizException）。配合全局异常处理器（@ControllerAdvice）统一捕获返回。避免设计过于复杂的异常继承体系，保持扁平。

7. 为什么阿里规约中禁止在 finally 中使用 return？

因为 finally 中的 return 会吞掉 try 或 catch 中的异常，导致异常被静默忽略，程序行为不可预期。编译器通常会对这种情况给出警告。
