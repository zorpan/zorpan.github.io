7.2.2 工厂方法模式（Factory Method）

定义创建对象的接口，让子类决定实例化哪个类。

7.2.3 策略模式（Strategy）

定义一系列算法，将每个算法封装起来，使它们可以互相替换。

Java 中的应用： Comparator 就是策略模式，Collections.sort(list, comparator) 可以传入不同的比较策略。

7.2.4 观察者模式（Observer）

定义一对多的依赖关系，当一个对象状态改变时，所有依赖它的对象都会得到通知。

7.2.5 代理模式（Proxy）

为其他对象提供代理以控制对目标对象的访问。

7.2.6 装饰器模式（Decorator）

动态地给对象添加额外功能，IO 流的设计就是经典案例。

7.2.7 模板方法模式（Template Method）

定义算法骨架，将某些步骤延迟到子类实现。

Java 中的应用： AbstractList、AbstractMap、HttpServlet.service() → doGet()/doPost()。

7.2.8 建造者模式（Builder）

将复杂对象的构建与表示分离，适合参数很多的场景。

7.3 SOLID 原则与实战应用

S — 单一职责原则（SRP）

一个类只有一个引起变化的原因。

O — 开闭原则（OCP）

对扩展开放，对修改关闭。通过抽象和多态实现。

L — 里氏替换原则（LSP）

子类必须能够替换父类，且不改变程序的正确性。

I — 接口隔离原则（ISP）

客户端不应该被迫依赖它不需要的接口。

D — 依赖倒置原则（DIP）

高层模块不应依赖低层模块，两者都应依赖抽象。

7.4 DRY、KISS、YAGNI 编程原则

DRY（Don’t Repeat Yourself）
不要重复自己。相同的逻辑只在一个地方定义，通过方法提取、继承、组合等方式消除重复。

KISS（Keep It Simple, Stupid）
保持简单。代码应该尽可能简单易懂，避免过度设计和炫技。

YAGNI（You Ain’t Gonna Need It）
你不会需要它。不要为未来可能的需求提前写代码，只实现当前需要的功能。

面试精选

1. 常用的设计模式有哪些？请举例说明。

创建型：单例（枚举实现、Spring Bean 默认单例）、工厂方法（BeanFactory）、建造者（StringBuilder、Lombok @Builder）。结构型：代理（Spring AOP、MyBatis Mapper）、装饰器（IO 流、Collections.synchronizedXxx）、适配器（HandlerAdapter）。行为型：策略（Comparator、ThreadPoolExecutor 拒绝策略）、观察者（Spring Event、MQ）、模板方法（AbstractList、HttpServlet）。

2. 代理模式和装饰器模式的区别？

代理模式关注控制对象访问（如添加权限校验、懒加载），代理对象通常不改变接口行为；装饰器模式关注动态添加功能（如加密、压缩），装饰器通常保持接口不变但增强行为。代理通常一对一，装饰器可以层层嵌套。Spring AOP 是代理模式，IO 流是装饰器模式。

3. 策略模式和工厂模式的区别？

工厂模式关注对象创建（”创建什么”），策略模式关注行为选择（”怎么做”）。工厂返回的是对象，策略返回的是算法。实际开发中两者经常结合使用：用工厂创建不同的策略实例，再注入到上下文中使用。

4. 什么是开闭原则？怎么实现？

对扩展开放、对修改关闭。新增功能时不修改已有代码。实现方式：通过接口/抽象类定义契约，通过多态和依赖注入实现扩展。Spring 中大量使用（如 BeanPostProcessor 扩展点、HandlerMapping 扩展）。

5. Spring 中用到了哪些设计模式？

工厂模式（BeanFactory）、单例模式（Bean 默认作用域）、代理模式（AOP）、模板方法（JdbcTemplate、RestTemplate）、观察者模式（ApplicationEvent）、策略模式（Resource 接口）、适配器模式（HandlerAdapter）、装饰器模式（BeanWrapper）等。

6. 什么是 DDD？和传统三层架构的区别？

DDD 以领域模型为核心，先理解业务再设计系统，关注限界上下文和聚合边界。传统三层架构按技术分层（Controller-Service-Dao），业务逻辑散落在 Service 层。DDD 将核心逻辑封装在领域模型中，贫血模型 → 充血模型，更适合复杂业务场景。

7. 单例模式有几种实现方式？推荐哪种？

五种：饿汉式、懒汉式（synchronized）、双重检查锁（DCL）、静态内部类、枚举。推荐枚举实现：天然线程安全、防反射攻击、支持序列化、代码最简洁。次选静态内部类：懒加载、线程安全、无锁性能好。
